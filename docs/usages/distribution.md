# Distribute Kotlin Library

## Release A Library Using The Plugin

We can distribute to other users a Kotlin library using native or third-party dependency, some requirements are necessary for Apple targets.

### Requirement

The user must :

- add the same native dependency used by the Kotlin library to his Xcode project.
- use the same version as the library use.

It will fix issues with linking, missing resources, App Store compliance, and more.

!!! note

    The user **doesn't have access** to the Kotlin library source code, which is great!

## Relocatable klibs

### The problem

The `.def` files generated by the plugin describe where the compiled Swift package lives on the
machine running the build. `cinterop` copies these options verbatim into the klib manifest:

```properties title="…-cinterop-MyBridge.klib/default/manifest"
libraryPaths="/Users/runner/work/my-library/SPM/spmKmpPlugin/myBridge/scratch/arm64-apple-ios-simulator/release"
linkerOpts=-L"/Applications/Xcode_26.5.app/…/usr/lib/swift/iphonesimulator" -F"/Users/runner/work/…/release"
```

This is invisible locally, since the paths are correct on the machine that produced the klib.
Once the library is published to a Maven repository, those directories don't exist on the
consumer's machine, and every Apple link prints:

```
ld: warning: search path '/Applications/Xcode_26.5.app/…/usr/lib/swift/iphonesimulator' not found
ld: warning: search path '/Users/runner/work/my-library/…/release' not found
```

### The fix

Set `publishSafe = true` on the packages of a library you publish:

```kotlin title="library/build.gradle.kts"
swiftPackageConfig(cinteropName = "myBridge") {
    publishSafe = true
    dependency {
        // ...
    }
}
```

It:

- omits `libraryPaths` from the generated definitions — `cinterop` already embeds the archive named
  by `staticLibraries` inside the klib (`default/targets/<target>/included/`), so consumers resolve
  it from there;
- removes the absolute `-F`/`-L` search paths from `linkerOpts`, keeping only relocatable options
  (`-framework`, and whatever you declare through `linkerOpts`);
- adds those search paths back on the link tasks of **your** project, so your own binaries
  (`linkDebugTest*`, frameworks, ...) keep linking exactly as before.

!!! note

    `compilerOpts` still carries the header search paths, because `cinterop` needs them to run.
    They are recorded in the manifest but never reach the linker, so they produce no warning.

### What consumers must do

Nothing changes for an application built by **Xcode**: the Xcode project supplies the frameworks,
as described in the [requirements](#requirement) above.

A binary linked by **Gradle** (`linkDebugTestIosSimulatorArm64`, a test executable, a framework
built without Xcode) has no Xcode to supply them. The consumer must point the linker at their own
copy of the dependencies, for example by applying the plugin in their own project, or:

```kotlin title="consumer/build.gradle.kts"
iosSimulatorArm64 {
    binaries.getTest("debug").apply {
        linkerOpts += listOf("-F", "<path to the compiled frameworks>")
    }
}
```

!!! warning

    Without `publishSafe`, that same binary would silently pick up the search paths of the machine
    that published the library — which is exactly what makes the failure confusing.

## Example

A Compose Multiplatform Component library using a native video player.

```kotlin title="commonMain/kotlin/KmpPlayer.kt"
@Composable
public expect fun KmpPlayer(modifier: Modifier = Modifier, url: String)
```

### Android
For Android, it uses [Exoplayer](https://github.com/google/ExoPlayer).

#### Gradle

```kotlin title="library/build.gradle.kts"
androidMain.dependencies {
    implementation(libs.media3.exoplayer)
    implementation(libs.media3.exoplayer.dash)
    implementation(libs.media3.ui)
}
```

#### AndroidMain

```kotlin title="androidMain/kotlin/KmpPlayer.kt"
@Composable
public actual fun KmpPlayer(modifier: Modifier, url: String) {

    val context = LocalContext.current

    // Initialize ExoPlayer
    val exoPlayer = ExoPlayer.Builder(context).build()

    val mediaSource = remember(url) {
        MediaItem.fromUri(url)
    }


    LaunchedEffect(url) {
        exoPlayer.setMediaItem(mediaSource)
        exoPlayer.prepare()
    }

    // Manage lifecycle events
    DisposableEffect(Unit) {
        onDispose {
            exoPlayer.release()
        }
    }

    AndroidView(
        factory = { ctx ->
            PlayerView(ctx).apply {
                player = exoPlayer
            }
        },
        modifier = modifier
    )
}
```


### iOS

For iOS, it uses [KSPlayer](https://github.com/kingslay/KSPlayer), it's a pure Swift library.

#### Gradle

```kotlin title="library/build.gradle.kts"
kotlin {
    iosArm64 {
        swiftPackageConfig(cinteropName = "appleDeps") {
            minIos = "13.0"
            minMacos = "10.15"
            minTvos = "13.0"
            minWatchos = "2.0"
            dependency {
                remotePackageBranch(
                    url = URI("https://github.com/kingslay/KSPlayer"),
                    products = {
                        add("KSPlayer")
                    },
                    branch = "main"
                )
            }
        }
    }
}
```

#### Bridge

Some tips [here](../section-help/tips.md#working-with-objcnamesclasses-types).

```swift title="src/swift/appleDeps/MEPlayerController.swift"
import Foundation
import KSPlayer

@objcMembers public class MEPlayerController: NSObject {
     private let player = IOSVideoPlayerView()

    override init() {
       super.init()
       KSOptions.secondPlayerType = KSMEPlayer.self
       player.delegate = self
       player.autoresizingMask = [.flexibleWidth, .flexibleHeight]
       player.contentMode = .scaleAspectFill
    }

    public func setMediaItem(videoUrl: URL) {
       player.set(
          url: videoUrl,
          options: KSOptions()
      )
    }

    public var playerView: NSObject {
       player
    }

    public func releasePlayer() {
       player.resetPlayer()
       player.removeFromSuperview()
    }
}
```

#### IOSMain

```kotlin title="iosMain/kotlin/KmpPlayer.kt"
import appleDeps.MEPlayerController

@Composable
public actual fun KmpPlayer(modifier: Modifier, url: String) {

    val playerController = MEPlayerController()

    val mediaSource = remember(url) {
        NSURL.URLWithString(url)
    }

    LaunchedEffect(url) {
        if (mediaSource == null) {
            throw Exception("Bad input URL")
        }
        playerController.setMediaItemWithVideoUrl(videoUrl = mediaSource)
    }

    DisposableEffect(Unit) {
        onDispose {
            playerController.releasePlayer()
        }
    }

    UIKitView(
        factory = {
            playerController.playerView() as UIView
        },
        modifier = modifier,
        update = {
        }
    )
}
```

#### Requirement

The setup guide of your library must contain the rule that [KSPlayer](https://github.com/kingslay/KSPlayer) package must be added to his Xcode project with the explicit version.
